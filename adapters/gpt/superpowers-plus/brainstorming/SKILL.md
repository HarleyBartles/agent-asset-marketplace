# Brainstorming Ideas Into Designs

Start by understanding the current context, then narrow the problem with one
focused question at a time. Propose a few reasonable approaches, call out the
trade-offs, and turn the chosen path into a short design before anyone writes
implementation code.

## Quick Pattern

1. Read the relevant files and docs.
2. Ask one question if the scope is still unclear.
3. Propose 2-3 approaches with a recommendation.
4. Write the design in small sections.
5. Do not move into implementation until the design is agreed.

## Guardrails

- Keep the design short when the task is simple.
- Prefer explicit trade-offs over vague optimism.
- Split large work into smaller subproblems before planning.
