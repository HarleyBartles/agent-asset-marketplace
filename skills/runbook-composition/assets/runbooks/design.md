# Design work

Use this guide when a change needs a choice about structure, behavior, or a consequential tradeoff before implementation begins.

Start from the user problem and the repository's existing boundaries. Inspect the nearest maintained guidance and relevant code. State the constraints, identify the real options, and compare them against the problem rather than treating the first plausible design as inevitable. Prefer a small, coherent boundary that can be reviewed and changed safely. Record material assumptions and decisions where future workers can find them.

The stage is complete when the chosen direction answers the problem, important tradeoffs and unresolved questions are visible, and the next work can be planned without inventing missing product intent.
