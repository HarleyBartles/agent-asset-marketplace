# Implementation work

Use this guide when carrying out an approved change in the repository.

Confirm the active worktree and read the specific guidance routed for the files and behavior in scope. Establish the smallest meaningful proof before changing implementation. Make one coherent change at a time, keep generated outputs under their declared source authority, and preserve unrelated user work. When an unexpected result appears, inspect its cause before changing the surrounding design. Run the repository's declared focused checks and complete gate at the points its workflow requires.

The stage is complete when the intended behavior is implemented, relevant evidence passes, the diff contains only understood changes, and any remaining limitation or handoff is recorded accurately.
