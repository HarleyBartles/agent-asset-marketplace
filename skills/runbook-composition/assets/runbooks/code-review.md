# Code review stage

Use this guide when a change is ready for an independent review or review feedback must be resolved.

Review the exact proposed change against its request, approved design, repository guidance, and available validation evidence. Look for behavior defects, unsafe boundaries, missing cases, and mismatches between claims and proof. Report actionable findings with the affected location and consequence; separate confirmed defects from questions. When feedback arrives, verify the underlying claim before changing code, then rerun the evidence relevant to the correction. Request a fresh review after material corrections.

This stage guide describes the review lifecycle. Reusable review principles may live in a separate concern playbook if the repository has one.

The stage is complete when material findings are resolved or explicitly accepted by the responsible human, the changed result has current evidence, and the review disposition is clear.
