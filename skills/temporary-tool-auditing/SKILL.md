# Temporary Tool Auditing

Use this skill when a scenario needs tool-use evidence. The stable Codex global hook runs across projects, but records only after its activation registry matches the declared parent session ID and exact worktree. Codex subagent events carry the parent session ID and retain child identifiers where available. Another session, including one in the same worktree, stays out of the run from the start. Devin Desktop selectors include session activity, while an individual child requires serialized dispatch attribution. Devin CLI remains unsupported. Evidence supports a bounded claim for verified coverage, not universal proof.

## Workflow

1. Identify the active runtime, runtime version, exact worktree, and intended subject. For Codex, prepare from the target parent session so the helper reads `CODEX_SESSION_ID`; verify it is present and binds to subsequent hook `session_id` values. Use the current isolated worktree when available, otherwise the project checkout. Put run data off-repository. Choose metadata-only `status` detail by default. It stores identifiers, tool name, and observed outcome, while `full-results` additionally stores sanitized arguments and result bodies. Each run caps events at 25 MiB, health records at 256 KiB, controls at 1 MiB, and the manifest at 2 MiB, with space reserved for teardown metadata. Persisted run evidence stays below 32 MiB even during atomic manifest replacement, excluding fixed-size copied helpers. If any limit rejects a write, stop the round, report capture as incomplete, and do not renew that run expecting missing evidence to return. Even sanitized full results may contain credentials, personal/payment data, source code, internal paths, or confidential content, and pattern filters cannot identify every sensitive passage.
2. Resolve this skill's installed directory and use `scripts/auditctl.py`. Run `--help`, then `prepare --check` and `prepare --apply` with a unique run directory, runtime, project, scenario question, assessment subject, and detail. Codex capture session comes from `CODEX_SESSION_ID`; do not substitute an unrelated chat/thread identifier. If unavailable, stop and report the missing runtime capability. Do not use Devin Desktop with Devin CLI. The default lease is 30 minutes; choose a shorter or longer positive duration only as needed.
3. Run `install --check`. For Codex this previews one stable hook dispatcher in `$CODEX_HOME/hooks.json` and an owned script under `$CODEX_HOME/tool-auditing/`; it does not change project trust. Run `install --apply` once if the dispatcher is absent, inspect its commands, and have your human partner review and approve this definition. Restart Codex once only if required to load the global definition. Keep this installation for later engagements. If the installed helper hashes differ from the source, inspect the helper diff and obtain human approval before `install --apply --refresh-global-helpers`; this replaces only owned helper files and leaves hook definitions unchanged. Refresh is refused while any engagement remains in the activation registry because changing helpers during capture could create an evidence gap; finish, disable, and purge all active engagements before retrying. Run `enable --apply` to add this run's parent session ID and exact worktree to the activation registry; Windows updates `CODEX_TOOL_AUDIT_ACTIVATION_FILE` in the current-user environment, which the hook rereads from the registry on every invocation. On other platforms, the dispatcher reads the activation file directly. Run `verify --apply`, make one harmless tool call in this parent session, and finish verification with its captured call ID. Confirm the event session ID matches the prepared parent ID and includes the expected worktree before starting the scenario.
4. Run `start --apply`, conduct a bounded round, then run `stop --apply` to close that round. Assess and report; if the human requests more scenarios or follow-up, keep the same activation and installation, then start another round. Do not reinstall between rounds. An explicit `renew --duration-minutes N --apply` extends the lease and refreshes the activation entry. If renewal fails, the previous lease remains in force; do not assume the requested extension took effect. Expiry creates a gap and requires a fresh verified interval before further capture. For Devin child subjects, the matching dispatch post is the completion boundary and the orchestrator/other agents must remain idle during that dispatch.
5. Run `assess --subject <selector>` and inspect the selected subject, detail level, covered intervals, unresolved count, coverage gaps, health records, limitations, and redaction paths. For Devin child attribution, only if the orchestrator and other agents remained idle during the serialized dispatch, run `assess --subject child:<dispatch-call-id> --confirm-parent-idle --apply`; this persists the orchestrator's positional-attribution self-attestation. Missing controls, incomplete coverage, unmatched calls, health failures, redactions, unconfirmed orchestrator idleness, or ambiguous subject attribution prevent a no-tools claim. For an absence claim, capture a fresh positive control after the subject has completed (or a matching Codex session-end event) to confirm the hook path remains available through the end of observation. State counts and outcome statuses as observed, with `observed-unknown` when the runtime does not establish a result. Use the assessment result to communicate the bounded claim, but do not persist a separate assessment file in the run directory.
6. When the engagement has fulfilled its purpose and no follow-up is pending, run `disable --apply`. For Codex this removes only this run's activation entry and clears the environment switch when no other activation remains; it does not uninstall the stable hook. Run `verify-teardown --apply --phase begin`, make a harmless tool call in the same session, then finish with `verify-teardown --apply --phase finish --canary-performed`. This checks recorder health, global registration, and that the post-disable call added no event. No restart is required for disablement. For Devin or a legacy project-local Codex run, use the runtime-specific removal and unload handoff in its reference. After verified disablement, run `purge --apply` and confirm `logs_purged: true` and `cleanup_required: false`. This removes event, health, and control logs, run-local helper copies, when present, and subject/question details from the manifest. Unknown files keep cleanup pending. If purge fails, report cleanup as unresolved.

This is operational evidence for an honest local agent in a trusted user account. It does not resist someone with access to change the hooks, activation registry, or evidence files. Boundary controls verify the hook at their own points only; a silent outage between them cannot be ruled out without runtime evidence, so report uncertain coverage rather than claim no tools.

The stable Codex dispatcher may remain installed and inert between engagements. One engagement may include several record/assess/report/resume rounds; cleanup is due when the purpose is fulfilled, abandoned, or cancelled and no follow-up is pending. If interrupted, inspect the manifest and activation registry, stop writes safely, preserve evidence needed for the claim, then disable and verify before purging. Expiry never completes cleanup. Start/end controls bound the hook check, but cannot detect a silent runtime outage between them; if activation state or hook availability is uncertain during the interval, report that interval as unverified. A failure, conflict, missing runtime, uncertain activation, or failed purge means report cleanup as pending.

## Runtime details

- Read [Codex hook behavior](references/codex.md) before using Codex hooks.
- Read [Devin Desktop hook behavior](references/devin.md) before using Devin Desktop hooks.
- Use [evidence limits](references/evidence.md) when interpreting or reporting results.

The recorder sanitizes every persisted payload. It covers common credentials and structured personal/payment fields, plus selected high-confidence free-text patterns. It cannot reliably recognize arbitrary source code, names, confidential business content, every locale's identifiers, or every secret format. Sanitization is a defensive filter, not a guarantee; purge the logs after they have proved the claim. Never deliberately send credentials through a test tool call. Keep full results off unless they are necessary.
