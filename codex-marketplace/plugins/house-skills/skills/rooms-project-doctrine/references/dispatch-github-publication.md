# Dispatch, GitHub, and publication posture

Use Rooms dispatch skills only when work crosses into worker/action mode. Conversation and analysis are not dispatch by default.

Dispatch route:

- The current Rooms dispatch route decides whether Rooms dispatch mode is active.
- The current Rooms dispatch preparation step prepares a complete worker-facing dispatch.
- The current Rooms dispatch gate preflights send-ready dispatches and material nudges.

Use the repo/GitHub proof surface for Rooms issue creation, comments, migration, and closure posture when repo, commit, branch, gitlink, publication, remote-head, or full-stack Rooms evidence matters.

Publication proof and issue-goal conformance are different lanes. A worker GREEN, commit, clean status, changed-file list, validation summary, or issue comment is not completion by itself.

For issue-backed work, preserve or require:

- `issue_goal_as_observable_state`;
- `repo_surfaces_that_should_reflect_goal`;
- `falsification_checks_run`;
- `worker_claim_vs_observed_state`;
- `judgment`.

Tracked source-controlled changes route through worker dispatches unless Harley explicitly authorizes a direct GPT exception.
