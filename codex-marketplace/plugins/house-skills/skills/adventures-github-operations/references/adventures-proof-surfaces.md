# Adventures proof surfaces

Load this reference only when package, receipt, image, asset, deck, visual bible, or issue-to-PPTX evidence is central to verification.

## Asset and source evidence

Check the source lane the issue names. Common falsification surfaces include project source indexes, asset indexes, source-package manifests, accepted source images, candidate images, rejected images, contact sheets, and asset-sheet outputs.

Do not collapse these states:

- accepted source image;
- generated candidate;
- rejected candidate;
- deterministic contact sheet;
- asset-sheet compile;
- visual bible guidance;
- receipt evidence.

## Image QA evidence

Accepted image QA is a review state. It can support deck assembly or asset promotion. It does not authorize a new image call, regeneration, or generative edit.

If image QA is missing for generated body-slide art that a deck depends on, the judgment is usually AMBER or BLOCKED unless the issue explicitly waived that QA lane.

## Deck package evidence

Separate proof, full, and final package claims.

- Proof packages can establish layout, image custody, or teaching viability when the issue asks for proof.
- Full or final packages need the expected PPTX, sidecar, notes, image inventory, and any issue-specific outputs.
- Sidecar contents are evidence of handoff state, not proof that the deck itself satisfies the story or teaching goal.

## Receipt evidence

Receipt zips prove only what their manifests, hashes, extracted embedded images, and summaries prove.

A receipt can support claims about package identity, embedded-image custody, and reproducibility. It does not by itself prove story quality, lesson clarity, Patch agency, or final deck readiness.

## Visual bible evidence

Visual bibles guide prompt, QA, repair, preserve, and extrapolation behavior. They are not authority to generate images and not acceptance of an image candidate.

When a worker return mentions a visual bible, verify whether the bible was source-backed, repo-indexed, and used as guidance rather than treated as a mutation authorization surface.

## Issue-to-PPTX evidence

For issue-to-PPTX work, check the issue goal against the whole production chain:

1. issue ingestion or production brief;
2. frame readiness;
3. deck plan;
4. deck image plan;
5. image preflight and current-turn authorization if images were generated;
6. image QA acceptance;
7. PPTX build;
8. presentation QA;
9. receipt generation when required;
10. publication and final issue/comment posture.

A chain can be partially valid and still not closure-ready.
