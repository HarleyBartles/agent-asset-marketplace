# Crew Gates for Boring Buster

Use this reference when a boring-buster target needs route interrogation: mutation authority, dispatch or implementation-route choice, source/repo/skill topology, tool transport, runtime discoverability, issue closeout, cleanup/recovery, durable route memory, artifact shape, or in-flight surprise.

This is a boring-buster adapter for GPT-wide Crew doctrine. It does not define Crew roles in full.

## Local use

Crew gates are active repair gates before blocker gates. A miss is usually a route-repair signal. Return terminal RED, BLOCKED, or AMBER_UNRESOLVED only when the missing gate cannot be satisfied lawfully in the selected lane.

## Role adapters

### Index: starting terrain

Check whether construction, topology, source basis, existing landscape, and live surface are known enough. For skill/proposal work, include the relevant existing skill landscape and whether the editable source is installed-only, repo-backed, or unknown.

Repair by inspecting available source/topology, separating verified from claimed context, or naming the exact missing source after discovery fails.

### Silk: reachable routes and false-goal traps

Map reachable candidates, legal-looking shortcuts, dead ends, wrong surfaces, and false-success paths. The common post-adoption trap is treating every interesting work item as worker-executable without proving the editable target, worker environment, and implementation-plan shape.

Repair by switching route: Linear worker route for repo-backed coding, native skill stack for GPT skills, GitHub Operations for proof, Linear Control Plane for connector mechanics, or legacy Plan B only when the default route is unavailable or rejected.

### Writ: authority and artifact shape

Prove which routes are lawful now. Check actor authority, surface authority, output shape, and mutation scope.

Repair by downgrading to recommendation, asking for the smallest missing authority, writing to Linear only when authorized, or changing output shape when it implies the wrong authority.

### Klause: readiness Plan A

Consume known terrain and Writ-proven routes. Select the boring-ready Plan A or return the target to the upstream role whose missing work prevents selection.

Plan A after adoption usually means Linear worker route for repo-backed coding, not legacy dispatch packets. For worker-send-ready coding issues, Klause requires the `writing-plans` implementation-shape gate before GREEN.

### Rollback: failure and booby-prize posture

Name pressures that could make implementation fail, drift, or return false GREEN. Add abort, cleanup, amber-safe return, Goal B, and booby-prize exclusions when knowable.

### Receipt: integrity and durable pickup

Verify the Crew chain stayed attached to the readiness claim. If durable pickup context is missing and the correct Linear issue/comment/project or repo location plus authority is known, write or propose the lawful durable record and rerun gates.

Receipt does not launder unresolved ambiguity or private worker chat into source truth.

## Composite decision

For GREEN, every applicable Crew question must be satisfied, explicitly not applicable, or safely deferred outside the lane. If a Crew gate fails but a repair route exists, repair when authorized. If the route cannot become boring today, return RED. If source, authority, tool access, or user steer is missing, return BLOCKED.
