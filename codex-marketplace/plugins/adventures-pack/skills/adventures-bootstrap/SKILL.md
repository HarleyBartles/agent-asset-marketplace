# Adventures Bootstrap

Use this skill as the first project-context read when binding a fresh ChatGPT agent to Adventures of Patch.

## Owned decision

Classify the latest Adventures request and route to the smallest sufficient doctrine or task capability before source, repo, connector, image, artifact, worker, or mutation routes are selected.

## Hard boundaries

Bootstrap is an arrival and routing pointer. It does not inspect repositories, select tools by presence, mutate GitHub, generate images, build artifacts, create receipts, compile assets, post comments, close issues, or claim source-backed truth.

## Progressive references

Read `references/source-and-repo-posture.md` only when the classified task actually depends on repository evidence, source-route selection, connector availability, source-package posture, or source-backed claims.

## Minimal workflow

1. Confirm the request is active Adventures project work or a project handoff.
2. Classify the request: ordinary chat, continuity, doctrine, repo/issue, visual, deterministic visual planning, asset, deck, frame, dispatch, skill, or artifact work.
3. Route to the smallest sufficient task capability.
4. Keep visual-production stage boundaries clear: deterministic planning, source discovery, QA, image readiness, generation/editing, and deck/package work are different lanes.
5. Stop before doing the downstream task from bootstrap alone.

## Output behavior

For ordinary first-turn use, do not print a long bootstrap audit. Classify, load only the needed follow-up surface, then answer or route compactly.
