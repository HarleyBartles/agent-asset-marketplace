# Dispatch, GitHub, and publication posture

Use Rooms dispatch skills only when work crosses into worker/action mode. Conversation and analysis are not dispatch by default.

Dispatch route:

- The current Rooms dispatch route decides whether Rooms dispatch mode is active.
- The current Rooms dispatch preparation step prepares a complete worker-facing dispatch.
- The current Rooms dispatch gate preflights send-ready dispatches and material nudges.

Use the repo/GitHub proof surface for Rooms issue creation, comments, migration, and closure posture when repo, commit, branch, gitlink, publication, remote-head, or full-stack Rooms evidence matters.

Publication proof and issue-goal conformance are different lanes. A worker GREEN, commit, clean status, changed-file list, validation summary, or issue comment is not completion by itself.

For issue-backed work, preserve or require:

- `issue_goal_as_observable_state`;
- `repo_surfaces_that_should_reflect_goal`;
- `falsification_checks_run`;
- `worker_claim_vs_observed_state`;
- `judgment`.

Tracked source-controlled changes route through worker dispatches unless your human partner explicitly authorizes a direct GPT exception.

## Devin-shaped Rooms repo cleanup campaigns

Rooms repo cleanup campaigns may be Devin-shaped. Prefer:

- one durable Linear parent issue with a clear repo target and issue goal;
- Linear documents as lane/subtask packets where a chunky cleanup campaign needs multiple seams, instead of spawning many child issues by default;
- one coherent PR unless a split condition triggers (too-large diff, unrelated concerns, protected surface, validation dependency, or repo boundary);
- mandatory worktree isolation: before mutation, Devin must work in a fresh dedicated worktree based on current `main` or the issue-specified base, and report worktree path, branch name, base commit, `git status --short` before mutation, and whether any pre-existing dirty state was present.

Keep Rooms-specific protected-surface law in Rooms wrapper references. Do not collapse Rooms doctrine into the generic GPT-wide worker skill.
