# Compression validity test

A zoom-out compresses an entity into a model, then tests whether the model can regenerate the entity's actual behaviour.

## Zoom out

Reduce the entity or event to one or more of:

- behavioural truth
- emotional posture
- interaction mechanic
- compression mode
- structural role
- timing model
- lifecycle phase model

The zoom-out should explain behaviour, preserve distinction, avoid overresolving ambiguity, and avoid symbolic mush.

## Zoom back in

Test the compression against actual persisted material:

- voice artifacts
- tweets or thread shape
- dialogue
- room behaviour
- timing
- interaction patterns
- manuscript excerpts
- canon/system surfaces
- archive-derived evidence when lawful

A good zoom-out can plausibly regenerate artifact shape. It does not merely feel emotionally true.

## Green examples as pattern types

- A character model that predicts voice timing and interaction choices.
- An event model that explains staggered participation and boundary behaviour.
- A room model that preserves how function changes by use rather than official status.
- An internal-misalignment model that preserves belonging while explaining imperfect execution.

## Not enough

These are not sufficient by themselves:

- a beautiful phrase
- a symbolic role
- an archetype
- a theme
- a vibe
- a diagnosis
- a model that only fits one selected artifact while breaking the wider pattern

## Artifact verification gate

`green_artifact_verified` requires checked source surfaces. If source surfaces have not been checked, use
`green_model_only` or `amber_artifact_needed`.
