# Requirements Elicitation operational guidance

## When to apply

Use when the requirements-elicitation skill loaded and the question is deeper than a single sentence:
- planning stakeholder interviews,
- writing user stories and acceptance criteria,
- validating requirements,
- tracing requirements to tests and releases.

## Stakeholder interviews

- Identify all stakeholders: users, sponsors, operators, and compliance reviewers.
- Ask open-ended questions first, then converge on goals, constraints, and success criteria.
- Record decisions and unresolved questions in the same place.

## User stories

- Use the form: As a <role>, I want <goal>, so that <benefit>.
- Keep stories small enough to deliver in a single iteration.
- Split epics by workflow step, acceptance rule, or data variation.

## Acceptance criteria

- Write criteria as Given/When/Then or concrete success measures.
- Avoid ambiguous adjectives; replace "fast" or "user-friendly" with thresholds.
- Include negative cases, edge cases, and non-functional expectations.

## Validation and traceability

- Review requirements with stakeholders before implementation begins.
- Prototype or walk through scenarios to surface hidden assumptions.
- Link each requirement to the test, decision, and release that validates it.
