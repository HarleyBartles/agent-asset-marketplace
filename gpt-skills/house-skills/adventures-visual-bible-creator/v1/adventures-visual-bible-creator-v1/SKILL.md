# Adventures Visual Bible Creator v1

Use this skill to author, update, normalize, or lock Adventures visual bibles for reusable visual asset classes.

## Owned decision

Decide whether a visual bible can be created or updated from the available evidence, should remain provisional, needs more accepted source evidence, or must route to visual preproduction, image QA, asset-sheet compilation, canon/repo publication, or issue work.

## Hard boundaries

This is deterministic no-credit visual doctrine work owned by GPT/project workflow. Do not generate or edit images, accept image candidates, run image QA, compile asset sheets, build decks, canonise assets into the repo, post comments, or mutate repositories. Generation-ready bible text is not image-generation authority. PIG may consume visual bibles as constraints inside a bounded production job, but PIG does not author, lock, canonise, or accept visual bibles.

## Progressive references

Read `references/visual-bible-creation-contract.md` when creating or updating a bible, classifying bible state, drafting prompt/QA/repair/extrapolation blocks, partitioning evidence, or deciding provisional vs locked status.

## Minimal workflow

1. Identify the asset class, source basis, and intended bible state.
2. Separate accepted evidence, repo-grounded facts, user context, synthesis, and missing/unverified material.
3. Draft or revise concise visual canon plus extractable positive prompt, negative prompt, QA hard gates, repair guidance, and extrapolation rules.
4. Mark provisional, locked, blocked, or ready for review with exact blockers.
5. Stop before visual mutation, QA acceptance, asset compilation, or repo publication.

## Source posture

Use current repo/source evidence when visual canon matters. Do not copy Patch-specific canon into other assets; copy the operational shape and level of detail only.
