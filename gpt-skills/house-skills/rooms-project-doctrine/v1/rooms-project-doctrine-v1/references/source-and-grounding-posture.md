# Source and grounding posture

Use `rooms-grounded-answering` for named Rooms book-world, repo, workflow, canon, archive, manuscript, actor, or domain claims. Inspect bounded relevant repo surfaces before affirmative answers when repo access exists.

Use `rooms-source-partitioning-v1` when an answer mixes evidence classes: repo-grounded, worker-report, conversation-derived, report-derived, search-only, inferred, unavailable, or not checked.

Source routes have different authority:

- Bound `file_search` GitHub is strong for broad discovery, stale-reference inventory, corpus-style reads, and finding unknown surfaces.
- Live GitHub API routes are strong for exact current issue threads, comments, files by path, commits, refs, PRs, compare operations, and authorized issue mutations.
- Search is discovery, not final grounding. A search miss does not prove absence.
- Conversation and session summaries are not repo truth.

When the needed route is unavailable, label the limitation instead of filling the gap from memory.

Do not treat `rooms-mostly` wrapper visibility as full-stack visibility. Respect submodule pointers and child repo heads.
