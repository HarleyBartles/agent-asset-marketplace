# Writing Skills

Treat skill writing like TDD for process documentation. First find where a
skill would fail in practice, then write the skill to close those gaps, then
check that the new wording actually changes behavior.

## Quick Pattern

1. Pick realistic pressure scenarios.
2. Note the exact failures or rationalizations.
3. Write the skill to address those failures directly.
4. Re-run the scenarios and refine the wording.
5. Keep the final skill short, searchable, and specific.

## Guardrails

- Use clear triggering language in the description.
- Keep the skill focused on one pattern or technique.
- Remove loopholes if the wording still leaves an easy escape hatch.
