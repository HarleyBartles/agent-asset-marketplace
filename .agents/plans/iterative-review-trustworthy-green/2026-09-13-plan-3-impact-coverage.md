# Plan 3: Impact Inventory, Coverage Planner, and Safe Reviewer Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` (recommended - tasks are sequential) or `subagent-driven-development` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the recall engine real: materialize the bound diff and canonical changed-surface seed at enumeration, seal the review-assignment and hypothesis-derivation policies into digest-bound reference documents, ship the structured reviewer report contract, make the kernel derive obligation status and record binding from report outcomes, build the exact-snapshot context package that every dispatch binds, and emit a deterministic coverage plan from the impact-map union.

**Architecture:** A new `review_core/surfaces.py` parses the unified diff into a canonical changed-surface list; `enumerate_acquisition` materializes `diff.patch` + `surfaces.json` into the acquisition dir and `acquire` re-verifies the patch digest against `snapshot.diff_sha256`. A new `review_core/report.py` implements the spec's section-4 structured reviewer contract: strict schema, role-discriminated assignment results, lawful verdict derivation, and `structured_output` digests for mapper/challenger products. Two new sealed policies (`review_core/assignment_policy.py` + `references/review-assignment-policy.v1.json`, `review_core/hypothesis_policy.py` + `references/hypothesis-derivation-policy.v1.json`) replace the `_Builtin*` stubs in `engine.load_witness_sources`; their digests are already bound into the snapshot subject by Plan 2 acquisition. In `policy.py`, `_install_attestations` gains report-derived binding checks (verdict, assignment set, dispatch, epoch), `_h_map_impact`/`_h_challenge_coverage` gain `structured_output` subject equality against the installed records, a new `_apply_obligation_outcomes` transitions obligation status from typed report results (the missing derivation: nothing currently ever sets `covered`/`not-applicable`), and `_install_obligations` gains an install-time floor check. A new `review_core/context_package.py` materializes the per-dispatch package (complete patch, surface files at head, authority bytes, hazard framing, instruction manifest) and `reviewctl` gains `package` and `plan-coverage` producer verbs.

**Tech Stack:** Python 3 (stdlib only, matching `review_core` conventions), `git` CLI for head-revision file reads, pytest for tests.

**Spec:** `.agents/specs/2026-08-21-trustworthy-iterative-review-design.md` sections 3 (coverage obligations), 4 (structured reviewer contract), 5/5a (roles, floors, independence) are normative for this plan; `.agents/specs/2026-09-12-iterative-review-calibrated-green-design.md` supplies the calibrated-green posture and Plan-2 deltas.

**Execution Strategy:** `executing-plans` - tasks are strictly sequential (Task 5 consumes Tasks 2-4, Task 6 consumes Task 1, Task 7 consumes all), each carrying its own TDD cycle and commit; subagent dispatch would only add context-shuffling for coupled interfaces.

## Global Constraints

- Threat model honesty: agents are assumed honest-but-fallible, not malicious. Findings must describe reachable divergences under that model; do not add active-adversary plumbing (tamper-proofing, hostile-runtime defenses) beyond the shipped tamper-evident contract.
- Runtime gate: no new live paths weaken `engine.detect_runtime` / `engine.RUNTIME_DEVIN_DESKTOP` or the off-Devin fail-closed bundle. The context-package builder and `plan-coverage` producer are deterministic pure helpers; `reviewctl package`/`plan-coverage` keep the existing `--apply`-free read posture (they emit payload files, never mutate state).
- Source custody: canonical edits land in `codex-marketplace/plugins/superpowers-plus/skills/iterative-review/`; `.agents/skills/iterative-review/` is regenerated by `py -3 tools/run.py installed-skills --apply`, never hand-edited.
- Sealed policies resolve from the shipped reference documents only. Consumer base-revision override for review-assignment/hypothesis policies is a deferred concern (discovery/feedback already have it); do not wire it here.
- Interim boundary, stated honestly: `sources.reviewer_dispatch` remains `None`; every dispatch-backed action stays `missing-witness-source`-blocked in production. Plan 3 ships the deterministic contract surface the Plan-4 live dispatch source will consume: report schema, payload derivation, package digests, kernel outcome application. Tests exercise the real kernel path through the established fake-source and walk-driver seams.
- Epoch binding stays fail-closed: every record this plan installs or derives carries the current `snapshot_epoch`/`snapshot_fingerprint`.
- Obligation floors are recomputed, never trusted: install-time checks require `minimum_capability_tier`/`minimum_reasoning_floor` at or above `obligation_floor(scope_level, risk, consequences)` (the sealed policy may raise, never lower).
- `structured_output` is consumed, never stored: mapper/challenger/reviewer structured outputs ride the attestation payload like `exemption_outcome` and are popped at install; the kernel enforces payload-internal consistency (`sha256_json(subject(record)) == structured_output.subject_sha256`). The completion witness binds the raw report bytes for audit; byte-level re-verification of payload claims against the witnessed report remains an audit-path property.
- No placeholders: every interface name, file path, and test name in this plan is the contract executors use.
- Verification: focused tests via `py -3 -m pytest <test-file> -x -q` run **from the worktree root**; the canonical gate is the tracked pre-commit hook (`ci --apply` + `ci --check --diagnostics`), never `--no-verify`.

class SurfaceParseError(Exception):
    """Raised when the bound diff cannot be parsed into surfaces."""

def parse_diff_surfaces(diff_text: str) -> tuple[dict, ...]:
    """Parse unified `git diff` output into the canonical changed-surface list.

    Each entry (sorted by path):
      {"path": "<repo-relative posix path>",
       "change_kind": "added"|"modified"|"deleted"|"renamed",
       "renamed_from": "<old path>"|None,
       "hunks": [{"old_start": int, "old_lines": int,
                  "new_start": int, "new_lines": int}, ...]}

    Fails closed on a malformed `diff --git`/`---`/`+++` header triple or a
    `@@` hunk header that does not parse; binary files produce an entry with
    `hunks: []` and `change_kind` from the header. A diff with zero file
    sections returns an empty tuple.
    """

def surfaces_document(surfaces: tuple[dict, ...]) -> bytes:
    """Canonical JSON bytes for `surfaces.json` in the acquisition dir."""
```

- `acquisition.enumerate_acquisition` gains two named artifacts in `out_dir`:
  - `diff.patch` - the exact diff bytes already hashed into `diff_sha256` (currently computed at `acquisition.py:224-227` and dropped).
  - `surfaces.json` - `surfaces_document(parse_diff_surfaces(diff_text))`.
- `LiveAuthorityDiscovery` / `_load_dir` gains a binding check: `diff.patch` must exist and `sha256_hex(bytes) == data["diff_sha256"]`; absent or mismatched -> `AcquisitionError("tampered-source", ...)`. `surfaces.json` must exist and re-parse to the same surface list as `diff.patch`; mismatch -> `AcquisitionError("tampered-source", ...)`. These are named artifacts, not `write_evidence` aliases - their binding runs through the snapshot field, not the evidence table.

class ReportError(Exception):
    """Typed report-contract failure. `.reason` is a stable code."""

# Role -> allowed assignment-result kinds, per spec section 4.
RESULT_KINDS = {
    "impact-mapper-semantic": frozenset({"impact-map"}),
    "impact-mapper-contract": frozenset({"impact-map"}),
    "scope-challenger": frozenset({"coverage-inventory"}),
    "obligation-reviewer": frozenset({"obligation"}),
    "exemption-challenger": frozenset({"exemption-challenge"}),
    "finding-adjudicator": frozenset({"finding-adjudication"}),
    "fix-reviewer": frozenset({"fix-review"}),
    "review-repair-verifier": frozenset({"review-repair"}),
    "blind-final": frozenset({"blind-final"}),
    "closure-auditor": frozenset({"closure-audit"}),
}

def parse_report(raw: bytes, *, role: str) -> dict:
    """Strict-decode and validate one reviewer report.

    Enforces the section-4 contract: exact top-level key set
    {schema_version, review_session_id, attestation_id, snapshot_epoch,
     snapshot_fingerprint, dispatch_id, reviewer, assignments,
     structured_output, findings, uncertainties, verdict}; schema_version == 1;
    reviewer block exact keys with profile/profile_sha256/capability_tier/
    reasoning_floor/model/reasoning/context_mode; every assignment has
    {assignment_id, result, notes} and result.kind in RESULT_KINDS[role] with
    the role-discriminated key set below (additionalProperties: false
    emulated by closed key sets); findings entries carry
    {title, description, locations, severity, evidence_ids,
     source_assignment_id}. Raises ReportError, never KeyError/TypeError.
    """

def derive_verdict(report: dict) -> str:
    """The lawful verdict from a parsed report.

    "incomplete" if any assignment result is incomplete; "findings" if the
    findings list is non-empty or any result is a finding-bearing outcome;
    "clean" only when every result is covered/not-applicable-type, findings
    and uncertainties are empty; "blocked" is never derived - a blocked run
    produces no report.
    """

def obligation_outcomes(report: dict) -> dict[str, str]:
    """{obligation_id: outcome} from an obligation-reviewer report."""

def verified_obligations(report: dict) -> tuple[str, ...]:
    """verified_obligation_ids from a fix-reviewer report (empty otherwise)."""

def structured_subject(report: dict) -> dict | None:
    """structured_output for mapper/challenger reports, else None."""

def report_to_action_data(action: str, report: dict, *,
                          attestation: dict, findings: list) -> dict:
    """Build the `data` payload complete_action consumes for `action`.

    Mapper actions -> {"impact_map": report["structured_output"]["record"],
                       "attestation": attestation + structured_output popped
                       through, "findings": findings}.
    challenge-coverage -> {"coverage_inventory": ..., "revised_obligations":
                       ..., "attestation": ..., "findings": ...}.
    Review actions -> {"attestations": [...] or "attestation": ...,
                       "findings": ...} per the action's payload grammar.
    The typed outcomes (obligation results, exemption outcome,
    structured_output) are attached to the attestation dict for the kernel to
    pop at install - matching the shipped `exemption_outcome` precedent.
    """
```
